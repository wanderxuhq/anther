# anther 设计文档

日期：2026-08-08
状态：已与用户逐节确认

## 1. 概述

**anther** 是一个 npm 项目，提供在移动端和桌面端浏览器内查看和编辑代码的网页应用（类似 code-server）。开发动机：code-server 的移动端体验差（UI 布局不适配、键盘/输入体验差、触控交互笨拙、性能差）。

**MVP 范围**：文件管理（浏览/新建/重命名/删除/目录）+ 代码编辑（CodeMirror 6）。不含终端、Git、搜索、认证。

**定位**：自用/局域网工具，优先移动端体验；架构预留公网扩展位。

## 2. 设计原则

### 2.1 无状态（硬约束，"不拉屎"）

应用自身不产生、不依赖任何持久化数据：

- **服务端零落盘**：不创建配置文件、缓存、日志；无数据库、无 session、无 cookie；进程重启 = 回到起点。服务端对磁盘的唯一写入 = 用户通过 UI 主动编辑保存的文件（用户自己的数据）。
- **客户端**：不写 localStorage（除下述两个明确用途：userId、标签副本）、不写 IndexedDB。
- **内存级状态允许**：标签列表等运行状态存在于服务器进程内存中，重启即消失。

### 2.2 移动优先

布局以竖屏手机为第一设计目标，桌面为延伸形态。默认只读模式（浏览场景），编辑为显式切换。

### 2.3 URL 状态化

打开 URL 即打开对应文件。URL 携带跨会话状态，短且可分享。

## 3. 技术选型

| 层 | 选择 | 理由 |
|---|---|---|
| 前端框架 | SolidJS + TypeScript | 编译期、细粒度响应式、运行时极小，移动端性能友好 |
| 编辑器 | CodeMirror 6（全端统一，移动+桌面） | 轻量（~300KB）、触控/IME 原生支持好、可后期接 LSP |
| 后端 | Node 原生 http + TypeScript | 零依赖、无状态应用下足够；复杂再考虑 Koa |
| 构建 | Vite | Solid 标准工具链 |
| 测试 | Node test runner（后端）、vitest + Solid Testing Library（前端） | 无额外框架依赖 |

明确排除：Monaco（体积大、触控差）、数据库、认证（MVP）。

## 4. 架构总览

单体 npm 包，一个 Node 进程。`anther` 命令以**当前目录为根目录**启动服务器，浏览器访问 `http://<host>:<port>`。

```
anther/
├── bin/anther            # CLI 入口：解析参数、确定根目录、启动服务器
├── server/
│   ├── http.ts           # 原生 http：路由分发、静态托管、SPA fallback、错误映射
│   ├── routes/
│   │   ├── fs.ts         # 文件 API：LIST / READ / WRITE / MKDIR / RENAME / DELETE
│   │   ├── tabs.ts       # 标签 API：LIST / OPEN / CLOSE / FRONT / RESTORE / HEARTBEAT
│   │   └── static.ts     # 托管前端构建产物（生产模式）
│   ├── files.ts          # 文件系统访问层：路径解析、目录穿越防护、根目录边界
│   ├── write-gate.ts     # 写入校验：请求级 ro 裁决（ro=0 放行），防绕过
│   └── tab-store.ts      # 内存标签存储：标签列表 + 用户持有关系 + 心跳超时
├── web/                  # SolidJS + CodeMirror 前端（Vite 构建，产物进 dist/）
│   └── src/
│       ├── url-state.ts  # URL parse/serialize 纯函数（单一入口）
│       ├── api.ts        # API 客户端（fetch 封装）
│       ├── stores/       # 响应式状态（当前文件、标签、只读模式、心跳）
│       ├── views/        # 视图注册表：filetree / tabs / （未来 git、search）
│       ├── editor/       # CodeMirror 6 封装（适配层）
│       └── App.tsx       # 根组件：布局断点、抽屉、工具栏
└── dist/                 # 前端构建产物，随包分发
```

**CLI 用法**：`anther [目录]` 以指定目录（默认当前目录）为根启动；`--port <n>` 指定端口（默认 3000）。写入权限无启动参数，由前端编辑模式（ro=0）在请求级裁决。

**数据流**：UI 操作 → 前端状态层 →（URL 同步 + API 调用）→ 服务端校验 → 文件系统/内存状态。服务端无内存依赖外的任何状态，每次请求独立自包含。

## 5. 后端设计

### 5.1 API 一览

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/list?path=` | 列目录（文件类型、大小、mtime，供文件树） |
| GET | `/api/file?path=` | 读文件（文本；非 UTF-8 检测并提示） |
| PUT | `/api/file?path=` | 写文件（只读模式 403） |
| GET | `/api/search?q=&case=&exclude=&path=` | 全局搜索（SSE 流式；file/done/error 事件；排除按目录名原样使用，无服务端默认；断开即停；上限 maxFiles 500 / maxMatches 5000） |
| POST | `/api/create` | 独占创建文件（O_EXCL，已存在 409 不清空；只读模式 403） |
| POST | `/api/mkdir` | 建目录（只读模式 403） |
| POST | `/api/rename` | 重命名（只读模式 403） |
| POST | `/api/delete` | 删除（只读模式 403） |
| GET | `/api/state` | 服务器状态（`allowWrites` 恒 true——写入由请求级 ro 裁决） |
| GET | `/api/tabs` | 拉取标签列表 |
| PUT | `/api/tabs/open` | 打开标签（记录持有） |
| PUT | `/api/tabs/close` | 关闭标签（检查存续条件） |
| PUT | `/api/tabs/front` | 设置前台标签 |
| PUT | `/api/tabs/restore` | 服务器重启后首个访问者恢复列表 |
| PUT | `/api/heartbeat` | 心跳上报（任何 API 请求顺带更新 lastSeen） |

### 5.2 路由规则

- `/api/*` → API 路由
- 静态资源（`/assets/*` 等构建产物路径）→ 直接返回文件
- `/` → index.html
- **其余 GET → SPA fallback：一律返回 index.html**（history 路由支持）
- 未知 API → 404 JSON

### 5.3 文件系统层（files.ts）

- 根目录边界：所有路径解析为相对根的规范化绝对路径；**目录穿越（`..`）一律拒绝（400）**
- 路径参数必须为根目录内真实存在的合法路径
- 非 UTF-8 文件：读取时检测编码（BOM/无效序列），MVP 只保证 UTF-8 写入，其余提示

### 5.4 写入校验（write-gate.ts）

写入权限 = 单条件：**请求携带的 `ro` 状态**（服务端无需启动参数，恒允许被授权写入）：

- 写请求携带 `ro=0`（前端编辑模式）→ 放行
- `ro=1`（只读）或缺失 → 一律 403（改 URL 参数也无法绕过——缺失/非 0 均拒绝）

前端按钮（工具栏 `✎` 切换）只是 UI 意图：切换只读/编辑只改 URL `ro` 参数与编辑器状态；服务端 write-gate 是最终裁决者。从编辑切回只读前，前端会立即 flush 防抖中的自动保存（此刻仍以 ro=0 发送），避免切换后保存请求 403。

### 5.5 标签存储（tab-store.ts）——内存级共享状态

**模型**：

```
tabs:  有序标签列表 [path, ...]
users: Map<userId, {front: path|null, opened: Set<path>, lastSeen: number}>
```

**userId**：客户端 localStorage 首次访问生成 UUID；同浏览器所有窗口共享 = 同一用户。服务器重启后未知 userId 自动视为新用户。

**标签生命周期**：

- 打开：`open {path}` → 该用户 opened 加入；若列表无此标签则追加
- 关闭：`close {path}` → 从该用户 opened 移除；若该用户 front 指向它则 front 置空
- 存续规则：**标签从列表移除 ⟺ 没有任何"活跃"用户把 front 指向它**
- 前台：`front {path}` → 该用户 front 更新（单值，最后请求胜出）

**心跳**：客户端每 30s 调 `PUT /api/heartbeat`（任何 API 请求顺带更新 lastSeen）。超过 90s 无上报 → 标记不活跃。**存续判定只考虑活跃用户**——不活跃用户的前台持有被忽略（他人可关闭该标签）。不活跃用户的 opened 集合保留但不参与判定。

**示例**：A 前台持有 T、B 后台持有 T、C 后台持有 T。C 关闭 T → 列表保留（A 仍活跃持有前台）。A 关闭/离线 → 无活跃前台持有者 → T 从列表移除，其他用户下次刷新可见。

**状态一致性约定**：拉取式同步，不推送。本地操作立即生效于本地 UI；与服务器的不一致是预期行为，刷新时以服务器为准。

**服务器重启恢复**：客户端 localStorage 保存标签列表副本（随标签列表变化持续更新）。服务器重启后内存为空，第一个访问者调 `PUT /api/tabs/restore` 恢复列表；**服务器内存非空即拒绝后续 restore**（并发边缘：谁先到谁生效）。恢复后服务器内存为绝对真源，其他客户端旧副本不再覆盖。

## 6. URL 状态协议

**形态**：history 路由（无 hash），服务端 SPA fallback 支持。

```
最简:  /src/index.ts
完整:  /src/index.ts?ro=1&theme=dark&fs=110
空:    /（无文件打开 → 文件树视图）
```

| 参数 | 含义 | 默认 |
|---|---|---|
| （路径部分） | 当前打开的文件路径 | 无 → 文件树 |
| `ro` | `1` 只读 / `0` 编辑 | `1` |
| `theme` | `auto`（跟系统 prefers-color-scheme）/ `light` / `dark` | `auto` |
| `fs` | 字号缩放百分比 85–130 | `100` |

**规则**：
1. **单一路径**：URL 读写只在 `url-state.ts` 模块（parse/serialize 纯函数，独立可测）
2. **同步**：状态变更 → `history.pushState` 更新 URL（不刷新页面）；页面加载 → parse URL → 恢复状态；浏览器前进/后退 → `popstate` 同步回来
3. **宽容解析**：未知参数忽略（向前兼容）；文件不存在/路径非法 → 降级到文件树，不报错
4. 路径特殊字符（`?`、`#`、空格等）由 encodeURIComponent 编码
5. 未来其他资源类型通过 query 参数扩展（如 `?view=git`），当前不做

**URL 只携带"当前文件 + 三个短参数"**：永不膨胀，任何平台分享无长度压力。标签列表不进 URL（见 §5.5）。

## 7. 前端设计

### 7.1 布局断点

| 断点 | 形态 |
|---|---|
| 竖屏 <600px | 顶部薄工具栏 + 全屏编辑器 + 左侧抽屉（滑出） |
| 横屏 600–1024px | 顶部工具栏 + 常驻窄活动栏 + 编辑器 + 侧栏常驻 |
| 桌面 >1024px | 顶部工具栏 + 活动栏 + 侧栏 + 编辑器（标签经侧栏标签视图管理） |

标签始终经抽屉/侧栏的标签视图管理，不设顶部标签栏（用户最初需求：标签不放顶部；桌面形态 2026-08-08 最终 review 确认修订为与横屏一致的侧栏标签）。

### 7.2 视图注册表（抽屉/侧栏可扩展）

抽屉/侧栏内容为**可插拔视图注册表**，每个视图实现统一接口 `{id, icon, title, render()}`：

```
MVP:   filetree（文件树）、tabs（标签列表）
未来:  git、search、... （注册即出现，骨架不再改动）
```

- 抽屉顶部图标行自动渲染注册表
- 竖屏：抽屉内两个视图共用（顶部切换）；桌面：活动栏图标切换
- 标签列表为纵向列表（完整文件名可见）、当前标签高亮、行尾 `×` 关闭

### 7.3 工具栏（竖屏）

顶部薄工具栏：`[☰ 菜单/抽屉]` + 当前文件路径 + `[✎ 编辑/只读切换]`。

### 7.4 手势（MVP 原则：不自定义手势）

- 编辑器内：CodeMirror 6 原生触控（点按定位、拖动选择、长按菜单）
- 抽屉：原生滑出/滑入 + ☰ 开合
- 标签：行尾 `×` 按钮关闭（不做滑动删除）
- 明确不做：下拉刷新、双指缩放编辑器字号、边缘手势拦截

### 7.5 虚拟键盘

- 布局高度统一用 `100dvh`（动态视口单位）；传统 `100vh` 在键盘弹出/地址栏伸缩时会错乱
- 编辑态聚焦 → 键盘弹出 → 编辑器自适应压缩高度，工具栏始终可见
- IME 中文输入：CodeMirror 6 原生支持 composition（真机必测项）
- 光标跟随：聚焦/输入时自动 scrollIntoView

### 7.6 编辑器封装（editor/）

- CodeMirror 6 通过**适配层**封装：UI 只与适配层对话，将来更换引擎不波及 UI
- 自动保存：编辑变化 → 防抖 1s → PUT /api/file；失败重试 3 次后 Toast
- 只读模式：编辑器切换只读态（readOnly）

### 7.7 前端状态

- stores：当前文件（URL 同步）、标签列表（服务器同步）、只读模式（URL + 服务器）、心跳定时器
- 标签前端显示：初始 = GET /api/tabs 全量；操作后本地调整；刷新 = 全量重来

## 8. 错误处理

全部 Toast + 降级，不弹窗打断：

| 场景 | 行为 |
|---|---|
| 文件不存在/路径非法 | Toast → 降级到文件树 |
| 只读模式写文件 | 403 → 提示切换编辑模式 |
| 写入失败（权限/磁盘满） | Toast → 自动保存有限重试（3 次） |
| 服务器重启/心跳断 | 静默重连，失败提示刷新 |
| 非 UTF-8 文件 | 读取时提示，MVP 只保证 UTF-8 写入 |
| 目录穿越/非法路径 | 服务端 400/403 |
